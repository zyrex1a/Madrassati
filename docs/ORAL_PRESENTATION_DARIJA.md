# Script ديال présentation orale — Madrassati

## 1) مقدمة قصيرة (30 ثانية)

السلام عليكم، اليوم غادي نقدم ليكم مشروع **Madrassati**، وهو prototype ديال منصة رقمية لتسيير مدرسة خصوصية فيها التعليم الابتدائي والإعدادي. الهدف هو تسهيل التواصل بين الإدارة والأساتذة وأولياء الأمور والتلاميذ، وتجميع خدمات بحال التسجيل، النقط، الغياب، الدروس، الفروض والأداءات فواجهة واحدة.

## 2) المشكل والحل (30–45 ثانية)

فبعض المؤسسات، المعلومات كتكون موزعة بين الأوراق والاتصالات وملفات مختلفة. هاد الشي كيصعّب تتبع النقط والغياب وطلبات التسجيل. Madrassati كتقترح فضاء رقمي مركزي: ولي الأمر يقدر يتبع المعلومات، الأستاذ يدبر الأنشطة الدراسية، والإدارة تتابع الطلبات والعمليات.

## 3) التقنيات المستعملة (45 ثانية)

- HTML5: بناء هيكل الصفحات والفورمات.
- CSS3: التصميم، الألوان، layout وresponsive styling.
- JavaScript: التفاعلات، معالجة الفورمات، وإرسال HTTP requests.
- Node.js: تشغيل JavaScript فالخادم.
- Express: بناء REST API وتنظيم routes وmiddleware.
- MySQL: تخزين البيانات فالجداول والعلاقات.
- mysql2: ربط Backend بقاعدة MySQL وتنفيذ الاستعلامات.
- bcryptjs: hash كلمات المرور.
- JWT: التحقق من هوية المستخدم فطلبات API.
- dotenv: حفظ إعدادات التشغيل خارج الكود.

## 4) Architecture (30 ثانية)

المستخدم كيتعامل مع Frontend فالمتصفح. JavaScript كيرسل request للـBackend باستعمال HTTP وJSON. Express كيتحقق من البيانات والصلاحيات، ومن بعد كيتواصل مع MySQL عبر mysql2. النتيجة كترجع JSON والواجهة كتقدر تعرضها.

## 5) Database (30–45 ثانية)

قاعدة البيانات فيها جداول بحال users وroles للحسابات والأدوار، students للتلاميذ، classes للأقسام، admissions لطلبات التسجيل، grades للنقط، attendance للغياب، lessons للدروس، assignments للفروض، support_sessions للدعم، payments للأداءات وnotifications للإشعارات. استعملنا Primary Keys وForeign Keys باش ننظمو العلاقات ونحافظو على سلامة البيانات.

## 6) Demo مقترح (دقيقة إلى دقيقتين)

1. عرض الصفحة الرئيسية والخدمات.
2. شرح نموذج التسجيل الأولي، وبيّن أن API كيسجل الطلب ويرجع reference.
3. عرض نافذة Login وشرح أن التحقق الحقيقي كيدوز عبر `/api/auth/login`.
4. عرض dashboard كواجهة توضيحية للأدوار.
5. فتح `database/schema.sql` وشرح جوج أو ثلاثة ديال العلاقات.
6. عرض `backend/server.js` وشرح middleware ديال authentication وواحد route بحال `/api/admissions`.

**تنبيه فالديمو:** الواجهات ديال dashboard فيها بيانات تجريبية؛ ما تقدمهاش على أنها بيانات جاية فعلاً من MySQL. الدفع بالبطاقة ما مفعّلش.

## 7) الخاتمة (15 ثانية)

هاد المشروع عطاني فرصة نطبق مفاهيم Frontend وBackend وREST API وSQL وAuthentication وRole-Based Access. المرحلة الجاية هي نربط جميع dashboards بالـAPI، نكمل إدارة الحسابات والصلاحيات، ونضيف الاختبارات وتحسينات الأمان قبل أي استعمال حقيقي.

# أسئلة ممكن يطرحوها عليك وأجوبة مختصرة

### علاش اخترتي MySQL؟
حيت البيانات مترابطة: التلميذ تابع لقسم، والنقطة مرتبطة بتلميذ ومادة وأستاذ. قاعدة علائقية بحال MySQL مناسبة لهاد العلاقات وكتوفر Foreign Keys وConstraints.

### شنو الفرق بين Frontend وBackend؟
Frontend هو الجزء اللي كيشوف ويتفاعل معاه المستخدم. Backend كيعالج الطلبات، كيتحقق من الصلاحيات، وكيطبق منطق التطبيق ويتواصل مع قاعدة البيانات.

### شنو هي REST API؟
طريقة لتنظيم التواصل بين التطبيقات عبر HTTP methods بحال GET وPOST وPATCH، وغالباً البيانات كتكون بصيغة JSON.

### شنو الفرق بين GET وPOST وPATCH؟
GET لجلب البيانات، POST لإنشاء مورد أو تنفيذ عملية، وPATCH لتعديل جزء من مورد موجود.

### علاش كنستعملو bcrypt؟
باش ما نخزنوش كلمة المرور الأصلية. كنخزنو hash، ومن بعد bcrypt.compare كيتحقق من كلمة المرور المدخلة.

### شنو هو JWT؟
Token موقّع كيصدر بعد login وكيستعمله العميل فطلبات محمية. Backend كيتحقق من التوقيع والصلاحية.

### شنو الفرق بين Authentication وAuthorization؟
Authentication كيتأكد شكون المستخدم. Authorization كيتأكد واش الدور ديالو مسموح ليه ينفذ العملية.

### شنو هو Foreign Key؟
عمود كيربط جدول بجدول آخر وكيحافظ على referential integrity. مثلاً `students.class_id` كيربط التلميذ بالقسم.

### واش المشروع Production Ready؟
لا، هو prototype تعليمي. الـAPI والـschema موجودين، ولكن dashboards مازال فيها بيانات demo وماشي كلها مربوطة بالـAPI. خاص تكملة الصلاحيات والاختبارات والحماية والنشر الآمن.

### شنو أكبر تحدي تقني؟
تنظيم العلاقات بين الأدوار والبيانات، وبناء middleware للتحقق من الهوية والصلاحيات، والتأكد أن كل مستخدم يوصل غير للمعلومات اللي مسموح ليه يشوفها.

### شنو غادي تزيد مستقبلاً؟
ربط جميع الواجهات بالـAPI، استكمال CRUD لكل دور، إضافة رفع الوثائق بشكل آمن، إشعارات حقيقية، اختبارات، logging، rate limiting، ثم الدفع الإلكتروني عبر مزود موثوق وwebhooks.

## كلمات تقنية خاصك تكون حافظ معناها

| المصطلح | المعنى المبسط |
|---|---|
| CRUD | Create, Read, Update, Delete — إنشاء، قراءة، تعديل، حذف. |
| API | وسيلة التواصل بين Frontend وBackend. |
| Endpoint | URL محدد كيتعامل مع عملية معينة. |
| Middleware | كود كيدوز قبل تنفيذ route. |
| Hashing | تحويل كلمة المرور لقيمة ما كتترجعش للأصل بسهولة. |
| Token | رمز كيثبت الجلسة/الهوية. |
| Schema | تصميم قاعدة البيانات والجداول والعلاقات. |
| Validation | التأكد أن البيانات المدخلة صحيحة. |
| CORS | سياسة كتحدد origins اللي مسموح ليها تنادي API من المتصفح. |
| Seed | سكريبت كيعمر بيانات أولية فقاعدة البيانات. |
