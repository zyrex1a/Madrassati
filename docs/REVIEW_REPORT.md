# تقرير المراجعة التقنية — Madrassati

## الخلاصة

المشروع فيه أساس مزيان لمشروع portfolio تعليمي: واجهة عامة، Backend Express، API، schema MySQL، JWT وbcrypt. ولكن النسخة الأصلية ما كانتش مكتملة كمنتج حقيقي، لأن بزاف من dashboard كان كيعرض بيانات تجريبية محلية وماشي بيانات قاعدة البيانات.

## الإصلاحات اللي تدارو

1. **JWT secret:** ما بقاش التطبيق يقبل secret افتراضي ضعيف فـ production؛ خاص `JWT_SECRET` يكون مضبوط.
2. **CORS:** ولى كيسمح غير بالـ origins المحددين فـ `APP_ORIGIN` (افتراضياً localhost:3000).
3. **صلاحيات الأستاذ:** تزادت مراجعة الولوج للتلميذ حسب القسم اللي الأستاذ مسؤول عليه أو مربوط به عبر `teacher_subjects`، وتطبقات على قراءة التلاميذ وإضافة النقط والحضور.
4. **الدروس والفروض والدعم:** تزاد تحقق من أن الأستاذ مسموح ليه يخدم مع القسم قبل النشر/الإنشاء.
5. **الأداءات:** الأستاذ ما بقاش يقدر يقرأ بيانات الأداءات؛ القراءة محصورة فالإدارة والمحاسب وولي الأمر والتلميذ مع التحقق من العلاقة.
6. **حالة التسجيل العامة:** endpoint ديال تتبع الطلب ما بقاش كيرجع اسم التلميذ أو الملاحظة الداخلية ديال الإدارة.
7. **التحقق من البيانات:** تزاد تحقق أساسي من البريد وكلمة المرور عند إنشاء حساب أو تلميذ، ومن قيم حالة الحضور.
8. **Admin seed:** تحيدات كلمة المرور الافتراضية المعروفة؛ خاص تحدد credentials قوية فـ `.env`.
9. **Frontend:** تزاد HTML escaping للقيم اللي كتتعرض فالجداول، وتحيد السلوك اللي كان كيقول للمستخدم إن طلب التسجيل تخزن تجريبياً ملي API يفشل.
10. **وضوح الوظائف:** توضّح أن الدفع بالبطاقة غير مفعّل وأن dashboards كتستعمل بيانات demo.
11. **Documentation:** تكتب دليل تقني بالدارجة، script ديال العرض الشفوي، API reference وchecklist.
12. **Git hygiene:** توسع `.gitignore` باش يستثني `.env` وملفات التشغيل والـcoverage.

## الملفات المحذوفة

- `.openai/hosting.json`: إعداد نشر خاص ببيئة استضافة معينة، ما محتاجوش التشغيل المحلي ولا رفع المشروع العادي لـ GitHub. ما تحيد حتى ملف من منطق التطبيق أو الصور المستعملة.

## الملفات اللي خاصها تبقى

- `dist/`: الواجهة وCSS وJavaScript والصور المستعملة.
- `backend/`: الخادم وseed.
- `database/schema.sql`: بنية قاعدة البيانات.
- `.env.example`: مثال الإعدادات، بلا أسرار حقيقية.
- `package.json` و`package-lock.json`: dependencies ونسخها.
- `docs/`: وثائق الفهم والعرض والاختبار.

## نقاط مازال خاصها الخدمة قبل production

- ربط كل dashboard ببيانات API الحقيقية؛ حالياً بعض النماذج كتخدم فـ `localStorage` فقط.
- تكملة حسابات ولي الأمر والأستاذ والمحاسب وربط ولي الأمر بالتلميذ من واجهات الإدارة.
- مراجعة جميع GET routes ديال الدروس والفروض وحصص الدعم باش تعرض غير بيانات القسم المسموح به حسب الدور.
- إضافة rate limiting لمحاولات login، logging، اختبارات آلية، validation أشمل، وسياسة CSP.
- التفكير فـ HttpOnly Secure cookies عوض localStorage لتخزين JWT، حسب تصميم الجلسات.
- رفع الوثائق بشكل آمن، نسخ احتياطي، HTTPS وسياسة حماية البيانات المدرسية.
- اختبار SQL مع MySQL فعلياً. فبيئة المراجعة الحالية تم التحقق من syntax ديال JavaScript، لكن dependencies ما كانتش متوفرة فـ npm cache، لذلك ما قدرناش نشغلو integration test كامل.

## حكم portfolio

يمكن تعرض المشروع كـ **Full-stack school management prototype** وتشرح فيه API وSQL وAuthentication وRole-based access. ما تقولش إنه نظام إنتاجي مكتمل أو أن كل dashboard متصل بقاعدة البيانات. هاد الشفافية كتقوي العرض ديالك وما كتضعفوش.
